# Internacionalização

Locales oficiais: **English (`en`)** e **Português (Brasil) (`pt-BR`)**. A preferência persistida no SQLite é `system`, `en` ou `pt-BR`.

## Seleção e persistência

`system` é o padrão para bancos novos e para o upgrade da versão 0.1. No desktop, `sys-locale` informa o locale do sistema; no frontend de desenvolvimento, usa-se `navigator.language`. Locales iniciados por `pt` usam `pt-BR`; os demais usam `en`. Uma escolha manual persistida prevalece sobre o sistema nos próximos lançamentos.

**Settings → General → Language** / **Configurações → Geral → Idioma** aplica a mudança sem reiniciar. O contexto `react-i18next` atualiza os componentes e o shell recebe `set_menu_language`, reconstruindo inclusive os menus nativos com os mesmos catálogos. A aparência tem sua própria preferência independente.

## Arquivos

```text
app/src/i18n/index.ts              inicialização, detecção, formatos e mensagens
app/src/i18n/locales/en.json       catálogo inglês
app/src/i18n/locales/pt-BR.json    catálogo português
```

Os catálogos são objetos planos, com `keySeparator=false` e `nsSeparator=false`. Chaves semânticas novas seguem grupos como `scientific.*`, `references.*`, `content.*`, `graph.*`, `general.*`, `menus.*`, `errors.*`. Chaves `copy.*` identificam os textos migrados da 0.1; o sufixo estável evita colisões entre textos parecidos. Não é necessário gerar novas chaves com hash: prefira nomes semânticos para alterações futuras.

`labels.*` traduz somente códigos canônicos conhecidos de navegação, etapas, status e categorias. `legacy.*` adapta mensagens de UI já persistidas por versões anteriores; mensagens técnicas desconhecidas recebem uma mensagem útil genérica e os detalhes ficam no log.

## Adicionar uma string

1. Adicione a mesma chave nos dois JSONs.
2. Use `const {t}=useTranslation()` no componente e `t('grupo.chave')`.
3. Use interpolação nomeada: `t('content.pageRange', {start, end})`.
4. Não componha frases traduzidas com fragmentos quando uma chave completa puder expressar o texto.
5. Para códigos internos, conserve o código no estado e traduza apenas a apresentação.

A tradução contém também tooltips, labels acessíveis, placeholders, empty states e menus. Não coloque textos novos diretamente em JSX ou atributos de UI. O teste estático cobre os componentes principais. Chaves novas precisam existir nos dois catálogos; há teste de paridade.

## Conteúdo científico não é traduzido

Nunca passe títulos, abstracts, nomes de autores, periódicos, headings originais, raw citations, trechos de origem ou notas do usuário por `t()`/`label()`. A UI traduz apenas o rótulo canônico `methods → Methods / Métodos`, por exemplo. O heading **Materials and Methods** recebido do documento continua exatamente no idioma da fonte. O nome expandido PETRUS permanece em inglês por identidade institucional.

## Formatos e fallback

Datas usam `Intl.DateTimeFormat` através de `toLocaleDateString` com o locale ativo. Contagens usam `Intl.NumberFormat` e o formatador numérico i18next; identificadores, DOIs, anos de publicação e números de página não são reformatados como quantidades locais.

`fallbackLng='en'` resolve uma tradução ausente em português pelo catálogo inglês. Uma chave completamente desconhecida produz **Text unavailable / Texto indisponível**, sem quebrar a interface. Em desenvolvimento, gera warning `[PETRUS i18n]`; no bundle de produto, não há gravação de traduções nem comunicação de rede. O teste verifica detecção, seleção manual, fallback, persistência, atualização imediata, formatos e ausência de copy principal fora dos catálogos.

## Adicionar um idioma

Crie outro JSON com as mesmas chaves e registre o resource e `supportedLngs` no inicializador. Atualize a política central `preferredLocale`, a validação do setting no engine, a seleção do catálogo dos menus nativos e o seletor General. Acrescente testes de persistência, formatos e paridade. Não crie condicionais de locale espalhadas nos componentes.
